# im

[English](README.md) · 中文

用手机上的聊天软件给 agent 下指令。在飞书、企业微信、钉钉或 QQ 里发一条消息,就会在一个真实
会话里驱动一次真实的 agent 回合,回复回到同一个聊天。每个聊天有自己的会话,跨消息、跨重启都
保持。

## 渠道

| 渠道 | 传输方式 | 是否需要公网地址 | 凭证 |
| --- | --- | --- | --- |
| 飞书 / Lark | 事件订阅(HTTP 回调) | **需要** | App ID、App Secret、Verification Token |
| 企业微信 | 自建应用回调(HTTP,XML + AES) | **需要** | Corp ID、Corp Secret、Agent ID、Token、EncodingAESKey |
| 钉钉 | Stream 模式(本机连出的 WebSocket) | 不需要 | Client ID、Client Secret |
| QQ | 官方机器人网关(本机连出的 WebSocket) | 不需要 | App ID、App Secret |

**"是否需要公网"是要先规划的那一列。** 钉钉和 QQ 是本机主动连出去,所以笔记本在 NAT 后面、
什么都不暴露也能用。飞书和企微是回调进来,dsh 必须能从公网访问——在 dsh Web 服务前面放一层
隧道或反向代理(它默认只绑定回环)。

> [!IMPORTANT]
> **个人微信不做,这是有意的。** 个人号没有官方机器人接口。能接进去的插件都在用 iLink、
> wechaty 这类**模拟微信客户端**的网关——违反微信服务条款,风险由账号承担。企业微信是这一路
> 唯一的官方接口,消息同样在手机上收发。确实必须要个人微信的话,
> [目录页](../../CATALOG.zh.md)里列了做这件事的插件,并已标注为非官方协议。
>
> 飞书的长连接模式也没走:它的帧是 protobuf,要用官方 SDK,就意味着引入依赖和构建链。本仓库
> 两者都不要,所以飞书走回调。

## 安装

```sh
dsh plugin --profile web add dsh-plugin-im
```

不配置就什么都不启用,而且**在你指定谁可以用之前,谁都不可以**:

```yaml
- id: im
  config:
    allowFrom: ['ou_你的_open_id']
    cwd: '/Users/you/code/project'
    dingtalk:
      enabled: true
      clientId: '…'
      clientSecret: '…'
```

> [!WARNING]
> `allowFrom` 默认为空,而空白名单**谁都不放行**。这是一个能读写文件、执行命令的机器的遥控器;
> 开放默认值的后果不是"少个功能",而是别人的消息以你的身份在跑。id 精确匹配,不支持通配符。
>
> 不知道自己的 id?先给机器人发一条消息——日志里会打出被拒绝的那个 id,复制进配置即可。

## 在聊天里怎么用

发任何内容,它就是 prompt。四个命令:

| 命令 | 作用 |
| --- | --- |
| `/new` | 为这个聊天开一个新会话 |
| `/stop` | 取消正在跑的回合,已排队的内容保留;没有回合在跑时会如实说明 |
| `/status` | 这个聊天对应哪个会话、工作区在哪、当前是否在忙 |
| `/help` | 列出这些 |

只是以斜杠开头的一行——`/usr/local/bin`、一个正则、一个路径——会原样作为文本发给模型,而不是
被当成未知命令拒掉。

回复在**回合结束时**一次发出,不做流式:聊天不是终端,一个 chunk 一条消息没法读。超过
`replyChars` 的回复按段落或换行切分并标上 `[1/3]`,你能看出后面还有没有。回合结束时如果什么
都没写,也会发一句说明——沉默是这个桥**最不能**被误认为的状态。

## 它不做的事

- **不转播其他界面。** 你在 Web UI 里发起的回合不会被转到聊天里,只有这个桥发起的回合才回复。
- **不代你审批工具。** 审批仍按会话的权限预设走。手机上你能用的控制手段是 `/stop`。
- **不收发图片和文件。** 文字进,文字出。

## 配置

| 键 | 默认值 | 决定什么 |
| --- | --- | --- |
| `allowFrom` | `[]` | 允许下指令的发送者 id;空 = 全拒 |
| `cwd` | *(dsh 自己的工作目录)* | 从聊天新建会话时的工作区 |
| `agentPreset` | *(部署默认)* | 这些会话用哪个预设 |
| `replyChars` | `1800` | 单条消息上限,超出切分 |
| `language` | `zh` | 机器人自己说的话用哪种语言(不影响模型回复本身) |
| `refusalNotice` | *(空)* | 回给未授权者的话;空 = 什么都不回 |
| `dedupeEntries` | `500` | 记住多少条已处理的消息 id |
| `lark` / `wecom` / `dingtalk` / `qq` | 关闭 | 各渠道凭证 |

所有字段都在安装表单里,不需要碰命令行。

## 验证状态

判断逻辑和线格式都有测试覆盖:白名单、重投去重、命令解析、回复切分、每个平台的验签与载荷
结构,以及"聊天消息 → 一次回合 → 回复"整条路径(对着假宿主跑)。测试覆盖不了的是真实账号:
**四个渠道都还没有对着真实平台联调过**,所以每个渠道第一次连接时盯一下,并看日志——每一次
拒绝、验签不符、断线重连都会写明是哪个渠道、因为什么。

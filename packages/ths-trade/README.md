# ths-trade(未完成:仅有 AX 探针)

用 Accessibility API 驱动本机同花顺 Mac 客户端下单的插件。**目前只有探针,没有插件本体**——先把可行性问清楚再写工具面。

## 已确认的事实(同花顺 Mac 5.2.2)

- bundle id 会变:`cn.com.10jqka.macstock` 与 `...macstockPro` 在同一份安装上先后出现(客户端自更新所致),所以按 `cn.com.10jqka.` 前缀匹配;它派生的 WebKit 子进程带同样的本地化名字,**绝不能被当成目标进程**。
- 客户端**不带 AppleScript 字典**,只能走 AX。
- 交易模块 `bundle4Trade.bundle` 是原生 AppKit(62 个 `JY*` nib),买入表单在 AX 树里是标准控件,可寻址。
- 客户端自带模拟交易(`JYUserMoNiBeginView`),开发期应全程用它。

买入界面元素(位置路径会随界面变化,每次用前重新 `dump`):

| 用途 | ref |
|---|---|
| 代码输入框 | `w0/t1` |
| 股票名称回显 | `w0/s5` |
| 价格输入框 | `w0/t0` |
| 数量输入框 | `w0/t2` |
| 可买数量 | `w0/b16` |
| 参考金额 | `w0/s11` |
| 确定买入 | `w0/b24` |
| 重填 | `w0/b17` |

三个输入框**没有 title/id/placeholder**,只能靠相邻标签("代码"/"价格"/"数量",x≈272)的几何关系识别。索引路径对界面变化很脆,插件里应改成按标签锚定查找。

## 关键结论:AXValue 写入不可用

`AXUIElementSetAttributeValue` 写入被接受、回读一致,但**同花顺完全不响应**:股票名称不回显、可买数量不计算、价格不自动填充。字段显示 `600519` 而应用内部状态仍是空的。

这比"写不进去"更危险——表单看起来填好了,此时点「确定买入」提交的是什么完全不可控。**所以 `set` 命令不能用于下单路径**,保留它只为诊断。

替代方案是 `type`:先设 AX 焦点(拿不到焦点就拒绝输入),再用 `CGEventPostToPid` 把键盘事件**直投同花顺进程**而不走全局事件流(用户中途切窗口也不会把数字打到别的应用)。**这条路尚未验证**,是下一步。

## 下单流程(设计,待实现)

失败的 `set` 试验反过来给出了验证手段:同花顺收到真实输入后会自己回显名称、算出可买与参考金额。

1. `type` 代码 → 读回名称非空,证明应用认了这个标的
2. `type` 价格 → 读回涨停/跌停,校验价格在区间内
3. `type` 数量 → **读回参考金额,与自己算的比对**——用应用自己的计算反向验证其内部状态与意图一致
4. 三项对齐后,走 `ctx.approval.request()` 请求人工授权(一次性、不可批量放行、自带审计事件)
5. 授权通过才 `press` 确定买入
6. 立刻切到「委托」页签回查,确认委托存在

GUI 下单拿不到券商返回的委托编号,第 6 步的回查是唯一收敛手段,"点了但不确定成没成"的窗口无法完全消除。

## 用法

```sh
cd native && swiftc -O -o axths axths.swift
./axths apps                    # 目标进程
./axths dump --depth 14         # AX 树
./axths read <ref>
./axths type <ref> <text> [--clear]
./axths press <ref>             # 只用于按钮,下单前必须人工授权
```

需要调用方进程拥有辅助功能权限。插件运行时该权限按**责任进程**归属,即宿主应用(dsh Desktop);宿主为 ad-hoc 签名,重新打包可能导致授权失效,需重新授予。

## 合规提醒

国内程序化交易按《证券市场程序化交易管理规定》需向券商报备;同花顺用户协议通常禁止外挂式自动操作。这些不影响技术可行性,但决定这个插件能做到哪一步——由使用者自行判断与承担。

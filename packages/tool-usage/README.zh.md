# dsh-plugin-tool-usage

[English](README.md) | 中文

计量一次会话在工具上真正花了什么——多少次调用、每个工具多慢、失败多少次——并把这份
账通过 `toolUsage` 服务暴露出来。

重活在出问题之前是看不见的:在转录里,一次全市场拉取和查一只股票长得一模一样,直到
其中一个超时。本插件让这个差别在会话还在跑的时候就看得见。

```sh
dsh plugin --profile web add dsh-plugin-tool-usage
```

真实调用实测:

```
Tool usage: 3 calls, 0 failed, 1.7s spent in tools.
  astock_market_bars: 1×  total 1.4s  mean 1.4s  p95 1.4s
  astock_financials: 1×  total 203ms  mean 203ms  p95 203ms
  astock_quote: 1×  total 107ms  mean 107ms  p95 107ms
```

## 工作方式

包装 `tools/execute`——超时、重试、指标的官方缝——并且**不改变调用本身**:转发 `next()`
并原样返回它的结果。抛异常的分发也会被计入(记账放在 `finally` 里),因为它同样花掉了
时间;漏掉它会让糟糕会话里最烂的工具看起来最便宜。

## 它暴露什么

**是服务,不是工具。** `ctx.toolUsage` 提供 `snapshot()`(可编程的总计与逐工具表)、
`report()`(上面那段文本)和 `reset()`。注册一个模型可见的报表工具,等于在每次请求的
提示词里描述一份没人要的报表;服务则让运维、UI 面板或其他插件在真正需要时去读。

**可选的预算提醒。** 设置 `budgetCalls` 或 `budgetSeconds`,会话越过任一阈值后,提示词
里会出现一小段说明:时间花在哪、该怎么办——改用批量调用、收窄窗口、复用已取的数据。
未超预算时文本为空、零贡献,所以普通会话不为这个插件付出任何代价。

**退出时留一份摘要。** 插件卸载(会话结束、服务重启)时把账写进日志,便于事后复盘。

## 两个值得知道的判断

**按总耗时排序,不按调用次数。** 值得看的是会话把墙钟花在哪儿了——调用一次花十二秒的
工具是,调用四十次每次一毫秒的不是。

**Code Mode 下不重复计时。** 一次 `run_code` 调用**已经包含**它派发的那些工具的耗时,
把每一行都加总会把 100ms 报成 204ms,还会让预算在一半阈值就误触发。因此每个工具仍记
自己的全部调用,但**会话总耗时只算模型直接派发的那些**。

**分位数只用最近的样本。** 每个工具默认保留最近 200 条耗时。分位数应当描述工具**现在**
的表现;把有史以来每一条都留着,只会让一小时前的冷启动永远拖着它。调用数与失败数则
是完整的。

## 配置

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `budgetCalls` | `0`(关) | 调用多少次后提示词开始提醒 |
| `budgetSeconds` | `0`(关) | 工具耗时多少秒后开始提醒 |
| `sampleLimit` | `200` | 每个工具保留多少条耗时用于分位数 |
| `topN` | `10` | 报告里列出几个工具 |
| `logOnDispose` | `true` | 卸载时把摘要写进日志 |

# dsh-plugin-tool-retry

[English](README.md) | 中文

对**可能会自行恢复**的工具调用失败做重试——被重置的 socket、限流、超时——但只针对
你声明为「可安全重复」的工具。

dsh 已经会重试模型请求(`dsh-llm-retry`),也已经强制工具超时
(`dsh-tool-call-timeout-policy`),唯独**没有人重试工具调用本身**。于是数据源在扫描
中途关掉一个连接,整个任务就结束了;而 agent 只被告知「数据不可用」,剩下的只能靠它
自己发挥。

```sh
dsh plugin --profile web add dsh-plugin-tool-retry
```

## 你不说,它什么都不重试

重复一个写入过、下过单、发送过东西的工具,就是把那件事做两遍。而工具契约里**没有
「幂等」这一项**——`isConcurrencySafe` 说的是能否并发,不是能否重复——所以只能由
运维来点名,默认列表为空:

```yaml
- id: tool-retry
  config:
    retryTools: ['astock_*', 'ainfo_*', 'web_fetch']   # 只填只读取数的工具
```

模式只支持完整名字或结尾 `*` 前缀,**刻意不用正则**:这份名单决定了什么可以被执行
两次,一个手滑写成能匹配一切的 `.` 不是值得支持的用法。

## 什么算值得重试

那些「请求没拿到应答」或者「应答说了稍后再来」的失败:socket 重置与 `fetch failed`、
`429`/`5xx`、中英文的限流提示、超时。而参数写错、权限被拒、文件不存在——这些重试
一万次也是同样的结果,只会让用户白等。

退避是指数增长并封顶的,因为值得重试的失败多半是对端在过载,紧凑循环正是把别人的
短暂拥塞变成自己故障的方式。

## 它绝不做的两件事

**绝不把失败变成成功。** 重试用尽后返回的是真实的失败,只多附一行说明尝试了几次——
这样模型会把持续性故障读成持续性的,而不是当成一次运气不好,从而如实上报而不是再
原样试一遍。

**绝不留下一次没人能叫停的重试。** cordis 的 waterfall 会**消费**监听器列表,所以
重复调用 `next()` 会直接抵达工具本体,**跳过所有已被取走的包装器**——包括官方的超时
策略。因此每次重试都在本插件自己加的截止时间下运行,并且是与调用方的取消信号**融合**
而不是替换。退避期间被取消时,返回已经拿到的那个失败,而不是再启动一次没人等待的尝试。

## 配置

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `retryTools` | `[]` | 可安全重复的工具;空表示什么都不重试 |
| `maxAttempts` | `3` | 每次调用最多尝试几次(含第一次) |
| `backoffMs` | `500` | 首次重试前的等待,之后翻倍 |
| `maxBackoffMs` | `8000` | 等待上限 |
| `retryDeadlineMs` | `120000` | 给每次重试单独加的截止时间 |

与 [`tool-health`](../tool-health)(记住什么在失败)和 [`tool-usage`](../tool-usage)
(计量花了多少)天然配套。

# 工具呈现模式

[English](presentation-modes.md) · 中文

一次会话里工具是原生调用、走 Code Mode、还是两者都行,**由 agent 预设选定一次,并作用于
这个会话里的每一个工具**。没有插件能选它,也没有插件能豁免。这份文档存在的原因是:这个选择
很容易为了某一个插件而做,然后悄悄改变了其他所有插件的行为。

## 三种模式

| 模式 | 模型能调用什么 | 额外加进提示词的段落 |
| --- | --- | --- |
| `native` | 所有工具,一次动作一次调用 | 无 |
| `code` | 只能调 `run_code`,工具在 TypeScript 程序里被分发 | 生成的 SDK,外加「只能调用 `run_code`」这条规则 |
| `both` | 两者皆可,模型每次自行选择 | 生成的 SDK |

`both` **刻意不带**「只能调用 `run_code`」那条规则——在这个模式下原生调用确实会执行,写上
就是假的。

预设用一行 `tool-presentation` 声明模式:

```yaml
- id: tool-presentation
  name: '@deepseek-ai/dsh-agent-tool-presentation'
  config:
    mode: both
```

这个声明挂在预设的 scope 上,覆盖挂到它下面的每一个 agent——**一个组合只能选一种呈现**,
同一 scope 里出现第二次声明会在挂载时直接报错。`code` 与 `both` 还要求宿主侧有 TypeScript
代码运行时;没有运行时却选了它们的预设会**在挂载时**失败并点名这一行,而不是等到第一次请求。

## 每种模式的代价

**`native` 会废掉「产物是数据而不是文字」的工具。** 全市场筛选类工具的规范值是几十万行,
`render` 故意只给摘要——几千行绝不能进模型上下文。原生调用下,模型拿到的只有那份摘要,
再没别的。而它未必会说自己拿不到:催生这份文档的事故,是模型跑去解压会话日志、写了一个伪造的
数据文件,然后自信地据此作答。

**`code` 会废掉 UI 卡片。** 在 `run_code` 里分发的工具调用**不带结果元数据**——code-dispatch
事件只有 `content` 和 `isError`——所以 `output.presentationMeta` 根本不会被投影,按工具名
注册的卡片永远收不到数据。不报错,卡片只是一直空着。所以凡是画卡片的插件,都必须在 README
里写明它需要 `native` 或 `both`。

**`both` 会把 `native` 那个洞重新打开。** 模型每次自己选,于是它**可以**原生调用一个纯摘要
的工具、然后拿不到数据。这种形态的工具必须自己拒绝原生路径——`exec.parent` 只在 `run_code`
子调用时存在,它的缺席就是判据——错误信息要写明改用 `run_code`,以及拿不到就如实说、别拼凑。

## 它是会话级的,不是插件级的

容易踩到的连带影响:

- **所有工具插件都受影响,包括你以后才装的。** 为了让某张图能画出来而选的模式,同时决定了
  你下个月装的第三方工具怎么被调用。
- **度量类插件也会看到子调用。** `tools/execute` 和 `tools/result` 对 `run_code` 内部分发
  的调用同样触发,所以把每次调用简单相加的度量插件,在 `code` 和 `both` 下会**重复计时**
  ——`run_code` 这层的耗时本就包含它派发的活。按 `exec.parent` 区分顶层与嵌套。
- **Code Mode 每次请求都要花提示词预算。** 除工具定义外,生成的 SDK 段落会把整个目录再以
  SDK 形式描述一遍。
- **卡片是「没有」,不是「坏了」。** 日志里找不到任何错误。`code` 下卡片空着,就是这个模式的
  预期行为。

## 对插件作者意味着什么

- 依赖 `presentationMeta` 的插件(任何卡片),**必须在 README 里写明需要哪种模式**。它在
  运行时既检测不到、也修不了。
- 如果一个工具的规范值才是产物、`render` 只是摘要,**就要拒绝原生分发**,并在错误里点名
  `run_code`。单只查询类工具不要加这个守卫——它们的 render 本来就是完整答案。
- **不要让插件自带预设。** 模式是部署决策,管的是这个会话能调用的一切;插件去改它,就是在改
  不属于自己的行为。写进文档要求,而不是替用户改。

## 部署方怎么选模式

预设随 dsh 发布,在 `config/agent-presets/` 下。要跑一个变体,把它复制到
`$DSH_HOME/.agent-presets/<名字>/`,改其中的 `tool-presentation` 行,然后选中它:

```yaml
# $DSH_HOME/profiles/<profile>/cordis.patch.yml
- id: agent-presets
  config:
    default: <名字>
```

出厂的 `standard` 是 `native`,`code` 是 Code Mode;把 `code` 复制一份、只把 `mode` 改成
`both`,正是「同一个会话里既要跑筛选、又要画卡片」的部署所需要的。预设改动需重启服务生效。
